Watch the 7-minute walkthrough

Publish Benable Lists From One Keyword: List Publishing. Recorded inside the app and narrated start to finish.

Read the video transcript

One keyword, a finished list. You want a Benable list full of good products, ready to share. List Publishing builds it from one keyword and publishes it to your Benable account.

Sign in to Benable first. First, sign in. Click Sign in to Benable and a browser window opens to log in. Other Benable butlers share that login.

Publish needs your OpenAI key. Publish stays switched off until your OpenAI key is connected, in AI and Data Keys. If it is missing, a notice near the top points you there.

Amazon products need the Creators API. When products come from Amazon, search uses your Amazon Creators API connection. Set it up in Amazon Butler, then Settings.

Watch it run, in the top bar. In the top bar, Watch it run shows or hides the browser windows automations use. It starts off on a new install.

Type your niche. Now the main input. Type a niche keyword, like kitchen gadgets or dog deals. Broad works, and specific works too.

List by: keyword or brand. List by can switch to Brand name. Then every list showcases one brand's products.

Pick your marketplace. Marketplace is where the products come from. Match it to your affiliate account, so the links earn commission.

Four list sources. List source has four choices. Marketplace uses that store. Retailers only uses Target, Walmart, and the App Store. Curated skips affiliate links. Non-product lists things not for sale.

Keep the first run small. Number of lists starts at 4 to 4. Use the same number in both boxes for an exact count. For a first run, try 1 to 1. Sections per list starts at 3 to 6.

Affiliate disclosure. Affiliate disclosure is the wording Butler adds, and it uses (AD) when blank. Pick the title, description, or notes. Only the description is ticked to start.

Open Advanced settings. More publishing options live in Advanced settings. Open it before your first real run.

Only products with a campaign. Only publish products with a campaign starts ticked. It keeps Amazon products in Creator Connections or with an SPCC offer. A list left with too few of them can be held instead of published, and the Latest run card says why.

Make lists public. Make lists public after create starts ticked. New Benable lists start hidden, and this makes them public. Untick it to review a list first.

Notes and covers. Skip per-product notes is for quick test runs, since notes help a list rank. Generate list covers is on to start.

Share your lists. Under Share your lists, Share new lists automatically is off to start. Turn it on and tick where to share, like Pinterest or Telegram. These use the Social Destinations you set up in Amazon Deals Butler.

List size. Hold lists too short to rank starts ticked. Butler tops up short lists toward your target. It treats 16 products as the minimum to rank, aims for 21, and trims to 25.

Retailer mix. Retailer mix can add a few non-Amazon items, like App Store apps, Target products, or your own links. All start off. With the campaign filter ticked, as it is to start, those extras are dropped, so untick it to keep them.

Get list ideas. The AI list-idea generator suggests list titles for a niche. It publishes nothing. List Idea Packs offer ready-made ideas by season or holiday.

The List Ideas queue. Ideas wait in the List Ideas queue. Type a title and press Add, or paste many niches, one per line.

Default output. Default output sets whether an idea builds one list or a full collection. Publish all queued runs every idea that is not done yet.

Auto-run. Auto-run works on a schedule. It is off until you switch it on. Choose every 1, 3, 6, 12, or 24 hours.

Custom schedule and active hours. Custom adds a time of day, certain days only, and a random delay. Only run during active hours is off to start. Once ticked, it skips runs outside your hours, which are set to 9 AM to 9 PM to start.

Lists per day. Lists per day runs that many times a day, publishing one idea from your queue each time. The runs spread across your active hours if you turned those on, or across the whole day if not. Leave it at 0 to use the schedule.

What each run does. On each fire sets the job. Choices include refreshing saved lists, publishing the current niche as a fresh collection, or publishing one new list from the queue. Refresh needs list addresses below.

Fix SPCC links. Fix SPCC links swaps in your accepted SPCC link on lists you already published. Check links is a dry run. Fix links asks you to confirm.

Organize into collections. Scan my profile suggests which lists belong together in a collection. Untick any you do not want. Applying asks you to confirm.

Watch the status pill. Once you click Publish, this pill names each step, like Finding products for your niche. Stop switches on only during a run.

Read the Latest run card. When a run ends, a Latest run card appears under this bar, with the collection, a predicted optimization score from 0 to 100 per list, and a link to each list.

If lists are held. If lists were held, the card says why. Publish them anyway turns off the filter that held them, and runs again.

Run totals and past runs. Run totals add up lists and products. Past runs shows your recent runs, with a Resume button when one can continue.

Next: Published Products. Then open Published Products to see every product you published and why it was picked, and List Optimize to audit a list and get fixes.

Your first run. So a first run goes: sign in, connect OpenAI and the Amazon Creators API, type a niche, set lists to 1 to 1, and click Publish. Then read the Latest run card.
