## Ce que fait Benable Comment Butler

Liker une collection Benable est le signal d'engagement le moins coûteux. Commenter est le cran au-dessus - un commentaire court et pertinent vous place dans les notifications d'un créateur avec plus de poids qu'un like. Benable Comment Butler écrit des commentaires générés par IA adaptés à chaque produit (tirés des détails produit Amazon) et les publie sur les éléments Benable dans votre file.

Si l'IA échoue pour une raison ou une autre (rate-limit, produit bizarre), Butler retombe sur une phrase canned pré-écrite de votre liste plutôt que sauter l'élément. Vous obtenez toujours un commentaire posté, jamais un passage à vide.

## Avant de commencer

- **Une session Benable active** dans Chrome.
- **Clé d'API OpenAI** dans **API Integrations** - génère les commentaires par produit.
- **1-10 URLs de boutiques Benable** des créateurs à qui vous voulez commenter.
- **Au moins 3-5 phrases canned de secours** dans le textarea canned-phrases (par ex. "Excellente sélection !", "Je l'ajoute à ma liste", "Exactement ce qu'il me fallait").

## Les trois modes

Comme Benable Butler, cet espace a trois modes échelonnés :

- **Dry run (par défaut)**: écrit les commentaires mais ne les poste pas. Les ressort dans le log de run pour que vous vérifiiez le ton avant de passer en live.
- **Preview**: génère un plan de commentaires que vous pouvez parcourir avant validation.
- **Live**: poste réellement les commentaires via votre session Benable.

Démarrez en Dry run. Lisez 20-30 commentaires générés. Si le ton vous convient, passez en Live.

## Votre première passe

1. Ouvrez **Comment Butler** sous Amazon Butler → Benable Butler (imbriqué).
2. Dans **Storefronts**, collez 1-10 URLs de profil. Une par ligne.
3. Dans **Mode**, laissez Dry run pour la première passe.
4. Dans **Phrases canned**, ajoutez 5-10 commentaires de fallback. Gardez-les assez génériques pour coller à n'importe quel produit (par ex. "Très belle sélection", "Je l'ajoute à mon panier", "J'adore la curation").
5. Dans **Caps & pacing** :
   - **Par run**: démarrez à 10. C'est le total de commentaires à travers tous les profils pour le run.
   - **Délai entre commentaires**: 15-30 secondes. Les commentaires ont plus de friction que les likes ; vous avez besoin d'un rythme plus lent pour éviter les rate-limits.
   - **Jitter**: variation aléatoire de ±2 secondes pour paraître humain.
6. Dans **Ton**, choisissez un descripteur (par ex. "amical + bref", "enthousiaste", "réfléchi"). Le modèle l'utilise pour styliser chaque commentaire.
7. Cliquez sur **Démarrer**.

## Sur quoi on commente

Deux options dans **Sur quoi commenter** :

- **Uniquement les produits publiés sur Amazon**: commente seulement les éléments qui lient vers Amazon (le plus courant, le plus pertinent pour les créateurs d'affiliation).
- **Tous les éléments de la liste**: commente tout dans chaque collection, y compris les éléments non-Amazon.

Par défaut Amazon-only. Passez à Tous seulement si vous voulez une portée plus large.

## Mode Discover

Le toggle **Discover** étend l'espace au-delà de vos boutiques listées. Activé, Butler parcourt les catégories tendance sur Benable et ajoute automatiquement les profils qui correspondent à la file de commentaires. Utile pour trouver de nouveaux créateurs dans votre niche ; désactivez quand vous voulez un contrôle strict sur qui vous engagez.

## Réglages dans la durée

- **Cap par run**: 10 est prudent. Au-dessus de 30 par run, ça risque de paraître spammy aux yeux de la modération Benable. Le cap par jour (champ séparé) est le plafond dur - restez sous 50 par jour même sur un compte établi.
- **Tous les N éléments**: commente seulement tous les N éléments d'une collection. Évite que vos commentaires saturent un seul créateur et paraissent inorganiques.
- **Descripteur de ton**: des tons plus précis produisent des commentaires plus précis. "Amical + bref, s'adresse au produit spécifiquement, sans points d'exclamation" surperforme un simple "amical".
- **Qualité des phrases canned**: les fallbacks se déclenchent quand l'IA échoue. De mauvais fallbacks vous font mauvaise figure. Passez 10 minutes à en rédiger 10 solides.

## Où vont les données

L'historique par commentaire (profil cible + élément + texte du commentaire + horodatage + flag IA-ou-canned) est stocké dans le cache preseed. Les KPI montrent les compteurs **Total** + **Cette exécution**.

## Pièges courants

- **"Clé OpenAI manquante"**: configurez-la dans API Integrations. Comment Butler peut retomber sur les phrases canned, mais il vaut largement mieux générer des commentaires frais.
- **Les commentaires échouent à se poster (l'UI a renvoyé une erreur)**: Benable a changé ses sélecteurs. Comment Butler affiche "Sélecteurs pas encore configurés" tant que l'inspection runtime n'est pas relancée ; la bannière de l'espace l'indique si ça arrive.
- **Chaque commentaire est canned**: votre clé OpenAI est invalide ou rate-limited. Vérifiez API Integrations.
- **Les commentaires paraissent génériques**: affinez le champ Ton et ajoutez du contexte spécifique au produit. L'IA utilise la description Amazon + votre ton ; si l'un des deux est faible, la sortie est faible.
