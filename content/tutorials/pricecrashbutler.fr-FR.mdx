## Ce que fait Pricecrash Butler

Un vendeur oublie parfois une virgule décimale. L'équipe catalogue passe parfois à côté d'une alerte. Quand ça arrive, un aspirateur à 400 $ apparaît à 4 $ et un créateur réactif peut publier l'offre avant qu'Amazon ne corrige le prix.

Pricecrash Butler est ce radar. Il tourne selon un planning, interroge l'Amazon Creators API sur les catégories que vous suivez, filtre chaque résultat par pourcentage de remise et, dès qu'un produit affiche ≥99 % de remise, l'envoie à **Daily Deals Butler** soit en **brouillon pour relecture**, soit en **publication automatiquement planifiée**.

Le seuil vous appartient : 99 % par défaut parce que c'est là que vivent les vraies erreurs de prix. Baissez-le à 75–85 % pour élargir le filet aux liquidations et surstocks.

## Premier passage

1. Ouvrez **Pricecrash Butler** dans le menu latéral (sous Orders Butler, groupe Amazon).
2. Sélectionnez au moins une **catégorie** à scanner. « All » couvre tous les rayons.
3. Choisissez le comportement à la détection : **Brouillon pour relecture**, **Planifier automatiquement** ou **Sans transfert**.
4. Cliquez sur **Lancer**.

## Scans récurrents

Activez la planification automatique (1h / 3h / 6h / 12h / 24h). Le 6h par défaut est un compromis entre réactivité et les quotas partagés de PA-API.

## Comment marche le « 99 % » réellement

La Creators API n'expose pas de filtre « remise minimale » côté serveur. Pricecrash itère chaque catégorie avec `sortBy: Price:LowToHigh` et filtre ensuite par `savingsPercent`. Les correspondances à 99 % sont rares — c'est exactement le but.

## Pièges fréquents

- Pas d'identifiants : ouvrez Paramètres → Intégrations API → Creators API.
- `429 RequestThrottled` : trop de Butlers tapent PA-API en même temps. Baissez la cadence.
- Aucun résultat à 99 % : c'est normal. Baissez le seuil.
