> **Beta workspace.** Relink Butler is shipping to early users and may behave unexpectedly on edge cases. Preview every change before applying it, and report bugs from the Feedback workspace if anything looks off.

## What Relink Butler does

If you switched your affiliate setup - say, from raw Amazon tags to Geniuslink for international, or from one link shortener to another - every existing post still points through the old provider. Relink Butler scans your published content, finds the old links, and rewrites them to use your new provider, without you having to re-edit each post by hand.

It supports four modes:

- **Host change**: swap the link host (e.g. `amzn.to` → `geni.us`) while keeping the ASIN.
- **Retag**: update affiliate tags inline (rare; mostly for region-tag changes).
- **Remint provider**: swap the entire affiliate provider, regenerating each link through the new one.
- **Find-replace**: manual string-level swap. Use this when the other modes don't fit.

The point is the same in every mode: keep the published content the same, change where the link routes.

## Before you start

- **The new affiliate provider configured** in **API Integrations**. Whatever you're switching to needs to be live first; Relink Butler routes new links through it.
- **At least one content scope** populated:
  - **Deals Influencer Butler posts** in `daily-deals/`'s post history.
  - **YouTube videos** uploaded via YouTube Butler.
  - **Pinterest pins** posted via Pinterest Butler (when it ships).
  - **Benable lists** published via Benable Butler.

If you haven't used the corresponding workspace, that scope has nothing for Relink Butler to walk.

## Running your first swap

1. Open **Relink Butler** under Amazon Butler.
2. In **Mode**, pick the swap type. **Remint provider** is the most common - use it when changing providers.
3. In **Scope**, tick which content surfaces to rewrite. Deals Influencer Butler is on by default; tick others as needed.
4. **Preview rewrites**: Relink Butler walks each scope, finds every affiliate link, and shows you a side-by-side diff: old link vs proposed new link, per row.
5. Review the diff. Untick anything that looks wrong.
6. Click **Apply approved** to commit the swap.

Deals Influencer Butler + Pinterest swaps happen in-app (just updating local databases). YouTube + Benable swaps require Chrome sessions because they have to edit published content remotely - Relink Butler launches Chrome the same way other workspaces do.

## What Relink Butler does NOT do

- **It doesn't delete the old link.** The publish history keeps both - the new replacement runs alongside. This matches Retag Butler's design philosophy: preserve history, route forward.
- **It doesn't touch raw Amazon links you posted manually outside InfluencerButler.** Only content posted through one of our scopes is tracked.
- **It doesn't fix dead products.** If an underlying ASIN is dead, the link still routes through the new provider but lands on a 404. Use **Retag Butler** for dead-ASIN replacement.

## Common gotchas

- **Preview is empty**: usually means the scope is empty. Verify Deals Influencer Butler (or whichever scope) has post history first.
- **"New provider not configured"**: finish setup in API Integrations before running. The Remint mode needs the new provider's API key to generate replacement links.
- **YouTube swaps slow**: YouTube only allows ~10 edits/hour without rate-limiting. Relink Butler honors this; let the run take its time.
