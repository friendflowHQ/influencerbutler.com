> **Espace en beta.** Relink Butler est en cours de déploiement auprès des utilisateurs avancés et peut se comporter de manière inattendue dans certains cas limites. Prévisualisez chaque changement avant de l'appliquer, et remontez les bugs depuis l'espace Feedback si quelque chose semble bizarre.

## Ce que fait Relink Butler

Si vous avez changé votre setup d'affiliation — par exemple de tags Amazon bruts à Geniuslink pour l'international, ou d'un raccourcisseur à un autre — chaque post existant passe encore par l'ancien fournisseur. Relink Butler scanne votre contenu publié, trouve les vieux liens et les réécrit avec votre nouveau fournisseur, sans que vous ayez à ré-éditer chaque publication à la main.

Il supporte quatre modes :

- **Changement de host** — change l'hôte du lien (par ex. `amzn.to` → `geni.us`) en gardant l'ASIN.
- **Retag** — met à jour les tags d'affiliation en place (rare ; surtout pour les changements de tag par région).
- **Remint provider** — change le fournisseur d'affiliation entier, en régénérant chaque lien par le nouveau.
- **Find-replace** — substitution manuelle au niveau chaîne. À utiliser quand les autres modes ne collent pas.

L'objectif est le même dans chaque mode : laisser le contenu publié identique, changer vers où route le lien.

## Avant de commencer

- **Le nouveau fournisseur d'affiliation configuré** dans **API Integrations**. Ce vers quoi vous basculez doit être prêt d'abord ; Relink Butler y route les nouveaux liens.
- **Au moins un périmètre de contenu** avec des données :
  - **Posts Daily Deals** dans l'historique de publication de `daily-deals/`.
  - **Vidéos YouTube** uploadées via YouTube Butler.
  - **Pins Pinterest** publiés via Pinterest Butler (quand il sortira).
  - **Listes Benable** publiées via Benable Butler.

Si vous n'avez pas utilisé le workspace correspondant, ce périmètre n'a rien à parcourir.

## Votre premier swap

1. Ouvrez **Relink Butler** sous Amazon Butler.
2. Dans **Mode**, choisissez le type de swap. **Remint provider** est le plus courant — à utiliser quand vous changez de fournisseur.
3. Dans **Périmètre**, cochez quelles surfaces de contenu réécrire. Daily Deals est coché par défaut ; cochez les autres selon besoin.
4. **Prévisualiser les réécritures** — Relink Butler parcourt chaque périmètre, trouve chaque lien d'affiliation et vous montre un diff côte à côte : ancien lien vs nouveau proposé, par ligne.
5. Revoyez le diff. Décochez ce qui paraît faux.
6. Cliquez sur **Appliquer les approuvés** pour valider le swap.

Les swaps Daily Deals + Pinterest se passent dans l'app (juste des mises à jour de bases locales). Les swaps YouTube + Benable requièrent des sessions Chrome car ils éditent du contenu publié à distance — Relink Butler lance Chrome de la même façon que les autres espaces.

## Ce que Relink Butler NE fait PAS

- **Il ne supprime pas l'ancien lien.** L'historique de publication garde les deux — le nouveau remplacement tourne à côté. Cela correspond à la philosophie de Retag Butler : préserver l'historique, router vers l'avant.
- **Il ne touche pas les liens Amazon bruts que vous avez postés manuellement hors InfluencerButler.** Seul le contenu publié via un de nos périmètres est suivi.
- **Il ne répare pas les produits morts.** Si un ASIN sous-jacent est mort, le lien route quand même via le nouveau fournisseur mais atterrit sur un 404. Utilisez **Retag Butler** pour le remplacement d'ASIN mort.

## Pièges courants

- **L'aperçu est vide** — généralement le périmètre est vide. Vérifiez que Daily Deals (ou le périmètre concerné) a un historique de publication d'abord.
- **"Nouveau fournisseur non configuré"** — terminez la configuration dans API Integrations avant de lancer. Le mode Remint a besoin de la clé API du nouveau fournisseur pour générer les liens de remplacement.
- **Les swaps YouTube sont lents** — YouTube n'autorise que ~10 éditions/heure sans rate-limiting. Relink Butler le respecte ; laissez l'exécution prendre son temps.
