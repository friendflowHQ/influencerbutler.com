> **Espace en beta.** Benable Butler est en cours de déploiement auprès des utilisateurs avancés et peut faire surface à des bugs dans les cas limites. Utilisez **Dry run** ou **Preview** avant de cliquer Publier tant que vous n'avez pas vu l'espace traiter votre niche proprement quelques fois. Remontez tout ce qui paraît bizarre depuis l'espace Feedback.

## Ce que fait Benable Butler

Benable est une plateforme de "listes achetables" où les créateurs publient des collections de produits curatées. Construire une collection Benable à la main est un long process : rechercher des produits dans une niche → choisir les ASIN qui collent → écrire titres + descriptions → publier sur Benable, liste par liste. Benable Butler exécute tout ce pipeline depuis un seul mot-clé de niche.

La sortie est une collection Benable complète : header, sous-listes, produits sous chaque liste, le tout avec du copy écrit par IA qui colle à la niche et au marketplace.

## Avant de commencer

- **Un compte Benable** avec votre lien d'affiliation sauvegardé dans **API Integrations**.
- **Clé d'API OpenAI** dans API Integrations - le modèle qui choisit les produits et écrit le copy.
- **Tag d'affiliation Amazon** pour le marketplace Amazon ciblé (amazon.com, amazon.co.uk, amazon.ca, etc.). Pour **Walmart**, aucun tag n'est nécessaire : les utilisateurs connectés résolvent les produits Walmart via le service de recherche partagé, et Benable attribue les liens publiés à votre compte créateur.
- **Le premier Publish** vous demande aussi de vous connecter à Benable dans la fenêtre Chrome que Butler ouvre - connexion manuelle une fois, ensuite la session persiste pour les runs suivants.

## Les trois modes (lisez ça en premier)

Benable Butler a trois boutons qui se ressemblent mais font des choses très différentes :

- **Dry run**: exécute uniquement le pipeline OpenAI + recherche de produits. Pas de navigateur, pas de publication. Écrit en console un résumé de ce que Butler *construirait*. Tokens OpenAI gratuits ; prend ~1 minute.
- **Preview**: comme Dry run plus l'écriture d'un rapport JSON + HTML que vous pouvez ouvrir dans votre navigateur. Permet de voir la structure complète avant de valider. Recommandé pour votre première exécution dans n'importe quelle niche.
- **Publish**: crée réellement la collection sur Benable via Puppeteer (automatisation navigateur). Utilise votre session Benable sauvegardée. Prend 5-15 minutes selon la taille de la collection.

**Règle du premier run** : Dry run une fois → Preview une fois → relire le rapport HTML → seulement ensuite Publish.

## Votre première collection

1. Ouvrez **Benable Butler** dans la barre latérale gauche, puis **List Publishing**.
2. Dans **What should we publish?**, tapez un mot-clé de niche (par ex. "cuisine minimaliste", "équipement course pour débutants", "rangement pour studio"). Les niches précises surperforment les larges.
3. Choisissez un **Marketplace** (amazon.com par défaut). Choisissez **Walmart** pour construire la collection à partir de produits Walmart au lieu d'Amazon.
4. Vérifiez que votre **handle Benable** se remplit correctement. Modifiez si c'est faux.
5. Cliquez sur **Dry run**. Relisez la sortie console - est-ce que Butler a compris votre niche ?
6. Si oui, cliquez sur **Preview**. Ouvrez le rapport HTML généré une fois terminé. Parcourez chaque liste et produit. Rejetez ce qui ne colle pas.
7. Si la prévisualisation est correcte, cliquez sur **Publish**.

Publish ouvre une fenêtre Chrome. Au premier run, vous vous connectez à Benable à la main ; les runs suivants réutilisent la session.

## Réglages dans la durée

- **Mot-clé de niche**: le bouton le plus important de tous. "Gadgets de cuisine" est trop large → Butler renvoie 50 produits au hasard. "Outils compacts pour cuisine en studio" est à la bonne taille → Butler renvoie une collection cohérente.
- **Publier uniquement les produits avec une campagne** (Paramètres avancés, Publication et couvertures) - activé par défaut. Activé, Butler ne garde que les produits Amazon ayant une campagne Creator Connections ou SPCC active, ce qui est idéal pour la monétisation mais peut laisser une liste de niche trop courte pour être publiée. Désactivez-le pour remplir les listes avec des produits normaux, quelle que soit la commission (voir la note "mise de côté car trop courte pour se classer" dans Pièges courants).
- **Taille de la collection**: Butler décide automatiquement du nombre de listes et d'éléments par liste selon la niche. Niches étroites : 3-4 listes ; niches larges : davantage.
- **Audience et Voix du créateur**: deux champs optionnels en haut. Remplissez-les ("mamans au budget serré", "chaleureuse, drôle, pratique") et Butler écrit chaque titre, description et note pour cette audience, dans cette voix.

## Ce qui fait gagner une liste (le guide d'engagement)

Nous avons étudié 6 226 vraies listes Benable pour comprendre ce qui génère vraiment de l'engagement, et Benable Butler construit désormais chaque liste selon ces résultats automatiquement. Vous pouvez retrouver ces mêmes règles à tout moment dans la carte **Guide des listes gagnantes** en haut du panneau :

- **De 16 à 30 éléments**, c'est l'idéal. Moins de 12, c'est la plus forte baisse d'engagement, et inutile de rembourrer au-delà de 30.
- **Les titres courts gagnent** : de 3 à 6 mots, pas de nombre en tête, pas de deux-points, un emoji au maximum. La chaleur à la première personne va dans la description, pas dans le titre.
- **Une description chaleureuse à la première personne** qui dit pour qui est la liste, donne une raison rapide de faire confiance à votre choix et annonce ce qu'elle contient.
- **Une image de couverture ou un emoji** sur chaque liste, et un compte Benable **vérifié** dès que possible, augmentent tous deux l'engagement.

Benable accorde aussi à une liste bien construite son **badge Optimized** et la visibilité dans le feed Discover qui l'accompagne. Butler construit pour les deux à la fois.

- **Taille de la liste**: Butler vise l'idéal de 16 à 30. Si une liste revient trop courte, Butler ajoute des produits pour la compléter vers votre **Taille cible de la liste**. Si elle n'atteint toujours pas le seuil de 16 articles dont Benable a besoin pour se classer, Butler **met la liste de côté** au lieu de publier une liste qui ne pourra jamais se classer. Le résumé du run indique quelles listes ont été mises de côté et pourquoi. Dans **Paramètres avancés**, vous pouvez fixer la **Taille cible de la liste** et une **Taille maximale de la liste** (les listes sont réduites à cette taille avant publication), ou désactiver la sécurité **Mettre de côté les listes trop courtes pour se classer** pour publier à n'importe quelle taille.
- **Mélange de boutiques**: Amazon reste la base de chaque liste, mais vous pouvez laisser Butler ajouter quelques éléments non-Amazon à forte valeur là où c'est pertinent. Activez les sources voulues dans **Paramètres avancés** : **vos propres liens** (collez votre boutique Etsy, votre site ou votre app, un par ligne), **Walmart** (quand votre compte Walmart est configuré), **apps de l'App Store** et **Target**. Butler garde le mélange léger et n'ajoute un élément non-Amazon que là où il a sa place.

## Où vont les données

Les collections générées sont journalisées par run dans le cache preseed (JSON + rapport HTML). Le côté Benable - la collection publiée - vit sur votre compte Benable.

## Pièges courants

- **Il n'y a pas d'interrupteur Etsy dans Mélange de boutiques**: Etsy ne fait pas partie des boutiques que Benable Butler peut chercher tout seul. Le Mélange de boutiques couvre Walmart, Target, les apps de l'App Store, les lieux locaux, les vidéos YouTube et les ressources web. Vous pouvez quand même mettre en avant des articles Etsy : ouvrez **Settings**, descendez jusqu'à **Mélange de boutiques** et collez les URL de vos annonces ou de votre boutique Etsy dans **Vos propres liens à mettre en avant**, une par ligne. Butler reconnaît les liens Etsy et les place dans les listes où ils ont leur place. Chaque liste ne garde que quelques emplacements hors Amazon, alors mettez vos liens les plus importants en premier.
- **Benable Butler n'affiche pas Publication de listes dans le menu de gauche**: sur les anciennes versions, elle était désactivée, donc le groupe s'ouvrait sur Produits publiés, Offres Benable et Optimisation de liste, sans rien qui crée une liste. Ouvrez **Paramètres**, descendez jusqu'à **Visibilité des espaces de travail** et cochez **List Publishing**. Elle apparaît sous Benable Butler immédiatement et le choix est conservé. Les versions récentes l'activent dès le départ.
- **Le champ Niche keyword n'a pas de bouton à côté**: il se lance avec **Dry run**, **Preview** et **Publish**, tout en haut du panneau, dans l'en-tête. En descendant pour saisir une niche, ces boutons sortent de l'écran, et le champ semble ne rien faire. Remontez et cliquez sur **Publish** pour lancer cette niche. La file d'idées de mots-clés, plus bas, est distincte et se lance avec son propre bouton **Publier toute la file**.
- **"Clé OpenAI manquante"**: configurez-la dans API Integrations.
- **Une liste en file d'attente reste sur En attente**: En attente signifie que l'idée patiente encore dans la file Idées de listes. Rien ne tourne en arrière-plan et actualiser n'y change rien. Cliquez sur **Publier toute la file** et laissez la fenêtre Chrome qui s'ouvre tranquille jusqu'à la fin, ou activez l'exécution automatique pour avancer dans la file au fil du temps. Ce même bouton relance aussi les lignes marquées Échec, donc tout ce qui n'est pas marqué Terminée est repris. Publiez une exécution à la fois, car plusieurs en même temps se bloquent mutuellement. Une ligne restée sur En cours pendant une vingtaine de minutes est marquée comme interrompue dans l'historique, où vous pouvez cliquer sur Reprendre.
- **"Benable n'a pas pu terminer la création d'une liste"** : le run s'est arrêté parce que deux créations de liste d'affilée n'ont pas abouti. Une création ratée laisse souvent une liste vide nommée **My new list** sur Benable, et c'est ce reste qui bloque la tentative suivante. Ouvrez votre compte Benable, supprimez toute liste encore nommée **My new list**, vérifiez que la fenêtre Benable est bien connectée, puis cliquez sur **Reprendre** sur ce run dans l'historique. Si le même message revient aussitôt, assurez-vous qu'une seule publication est en cours. Sur les anciennes versions, ce même message pouvait aussi apparaître quand la fenêtre Chrome se fermait en cours de route, ce qui n'a rien à voir avec des listes restantes ni avec votre connexion : si la fenêtre a disparu quand le run s'arrête, lisez plutôt l'avant-dernier point ci-dessous.
- **"Connexion Benable requise"** pendant Publish - première configuration ou session expirée. Connectez-vous via la fenêtre Chrome ouverte, cliquez sur Reprendre.
- **Une liste publiée a son titre mais rien dedans, ou le run s'arrête avec "The Benable browser window closed"** : la fenêtre Chrome ouverte par Benable Butler a disparu en cours de route, donc plus rien n'a pu être ajouté ensuite. Laissez cette fenêtre tranquille pendant le run : ne la fermez pas, ne quittez pas Chrome et ne vous déconnectez pas depuis celle-ci, et évitez de lancer en même temps un autre butler qui pilote un navigateur. Pour vous en sortir, ouvrez votre compte Benable, supprimez la liste à moitié construite, puis relancez le run. Un run qui se termine avec environ la seconde moitié de ses articles marqués en erreur, c'est la même chose : ce décompte marque le moment où la fenêtre a disparu, pas des produits défectueux.
- **La collection publiée a moins d'éléments que la prévisualisation**: Benable rejette les ASIN non disponibles dans le marketplace choisi. Le log de publication montre ceux qui ont été ignorés.
- **Une liste de la prévisualisation n'a pas été publiée**: si une liste n'a pas pu atteindre le seuil de 16 articles dont Benable a besoin pour se classer, Butler la met de côté pour ne pas publier une liste qui ne peut pas se classer. Le résumé du run indique ce qui a été mis de côté et son nombre d'éléments. Élargissez la niche, ou désactivez **Mettre de côté les listes trop courtes pour se classer** dans Paramètres avancés, pour la publier quand même.
- **Rien n'est publié et le run se ferme au bout d'une ou deux minutes**: Benable trouve ses produits via votre connexion à l'API Creators d'Amazon. Si Amazon rejette ces identifiants, toutes les recherches reviennent vides et le run se termine tôt sans rien produire. L'indice: Deals Butler échoue sur tous les mots-clés dans la même session. Ouvrez **Amazon Butler**, puis **Paramètres**, trouvez la carte API Creators et cliquez sur **Tester la connexion**: elle affiche la raison exacte, le plus souvent un Client ID ou un Client Secret à recopier depuis votre compte Amazon Creator Connections. Les versions plus récentes le disent pendant le run au lieu d'annoncer "pas assez de produits correspondants".
- **Vous n'avez pas encore de connexion à l'API Creators d'Amazon**: Benable construit ses listes Amazon entièrement à partir de cette connexion, donc tant qu'elle n'est pas configurée un run Amazon ne trouve rien et se ferme sans rien publier. Vous pouvez quand même utiliser Benable en attendant. Mettez **Source des listes** sur **Détaillants uniquement (Target, Walmart, App Store)** pour des listes entières qui évitent Amazon et sont monétisées via Benable, ou sur **Sélection, sans liens (Maps, apps, vos liens)** pour des listes sans aucun lien produit affilié. Revenez à **Marketplace (à gauche)** une fois que Test connection passe dans Amazon Butler, puis Settings.
- **Vous avez choisi une source de listes autre qu'Amazon et Amazon s'ouvre quand même**: vérifiez que l'app est à jour. Dans les versions antérieures au correctif, le réglage **Source des listes** était respecté par le bouton principal **Publier**, mais pas par la file d'idées de mots-clés (**Publier toute la file**), qui empruntait quand même la voie Amazon et laissait les idées en attente sur En attente. Ces versions ouvraient aussi une page Amazon avant chaque run de publication pour chercher des liens sponsorisés, quelle que soit la source choisie. Sur une version ancienne, publiez avec le bouton principal Publier plutôt qu'avec la file d'idées, et désactivez **Publier uniquement les produits Amazon SPCC ou Creator Connections**, car ce filtre ne garde que les produits Amazon avec campagne et vide donc une liste Détaillants uniquement ou Sélection.
- **Toutes les listes sont mises de côté car trop courtes pour se classer**: **Publier uniquement les produits avec une campagne** (Paramètres avancés, Publication et couvertures) est activé par défaut. Il ne garde que les produits Amazon qui ont une campagne Creator Connections ou SPCC, et la plupart des produits courants n'en ont pas, donc les listes passent sous le seuil de 16 articles et sont mises de côté. Vous n'avez pas besoin de vos propres campagnes pour utiliser Benable Butler. Désactivez ce réglage pour remplir les listes avec des produits normaux, puis relancez. Si une liste reste trop courte, désactivez **Mettre de côté les listes trop courtes pour se classer** ou assouplissez les filtres de note et d'avis.
- **Niche trop étroite**: si Dry run renvoie <5 ASIN candidats, votre niche est trop serrée. Élargissez d'un cran.
- **Votre fournisseur GeniusLink (ou un autre DeepLink Routing) n'est pas utilisé sur les listes Benable**: DeepLink Routing, dans API Integrations, concerne les butlers qui publient eux-mêmes des liens, comme Deals Butler et Link Butler. Benable Butler est différent, car le lien vit sur Benable et non dans une publication: les articles sont donc ajoutés via le lien d'affiliation propre à Benable, ou avec le vrai lien Sponsored Products for Creators quand le produit a une campagne acceptée. Choisir GeniusLink à cet endroit ne changera pas la destination d'un article publié sur Benable. Faire passer les articles Benable par un lien intelligent est une demande de fonctionnalité notée chez nous, pas un réglage qui vous manque.
- **Votre niche est réécrite en liste d'achats, ou tous les articles viennent d'un seul magasin** : ce sont deux réglages différents, côte à côte en haut de List Publishing. Le sélecteur **Marketplace** à gauche décide de quel magasin viennent les produits, donc le laisser sur Walmart ou Amazon + Walmart explique qu'une liste entière arrive de Walmart. **Source des listes** décide de quel type de choses la liste est faite. Sur **Marketplace (à gauche)**, chaque article doit être quelque chose d'achetable, donc une niche qui ne l'est pas est déviée vers ce qui s'en rapproche le plus : demandez "hôtels du centre de Charleston" et vous obtenez des oreillers de voyage, avec la liste renommée en conséquence. Pour des lieux, choisissez **Recommandations hors produits (lieux, vidéos, apps, ressources)** et activez **Mélanger des lieux locaux** dans Mélange de détaillants. Pour des listes entières d'autres magasins, choisissez **Détaillants uniquement (Target, Walmart, App Store)**. Les interrupteurs de Mélange de détaillants, y compris **Mélanger Target**, ajoutent seulement quelques articles hors Amazon à une liste majoritairement Amazon ; ils ne changent pas le marketplace. Les lieux locaux, les vidéos YouTube et les ressources web nécessitent votre clé OpenAI configurée dans API Integrations.
